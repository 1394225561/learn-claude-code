第 16 课: Team Protocols — 团队协议

上一课的团队通信是松散的文本消息。这一课用结构化协议实现可靠的请求-响应匹配。

问题：松散消息不可靠

Lead 发送"请关闭"，Teammate 回复"好的"。但如果 Teammate 回复的是"我正在做别的事情"呢？文本消息没有类型验证，容易误判。

协议状态机

@dataclass
class ProtocolState:
    request_id: str       # 唯一标识
    type: str             # "shutdown" | "plan_approval"
    status: str           # pending → approved / rejected
    payload: str
    created_at: float = field(default_factory=time.time)
  shutdown 请求:
  Lead ──[shutdown_request]──> Teammate
  Lead <──[shutdown_response]── Teammate

  plan_approval 请求:
  Teammate ──[plan_submit]──> Lead
  Teammate <──[plan_approval]── Lead

请求-响应匹配

pending_requests: dict[str, ProtocolState] = {}

def match_response(response_type, request_id, approve):
    """验证响应类型是否匹配请求"""
    state = pending_requests.get(request_id)
    if not state:
        return

    # 类型验证：shutdown 请求只能用 shutdown_response 回复
    if state.type == "shutdown" and response_type != "shutdown_response":
        return  # 类型不匹配，忽略

    state.status = "approved" if approve else "rejected"

前端类比

这就是 WebSocket/gRPC 的请求-响应关联模式。每个请求有唯一 ID，响应处理器匹配回来。状态机（pending → approved/rejected）和 Redux saga 或 XState 一模一样。

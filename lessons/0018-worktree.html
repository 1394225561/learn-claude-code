第 18 课: Worktree — 工作树隔离

多个 Agent 并行修改同一个仓库会冲突。这一课用 git worktree 让每个任务拥有独立的文件系统。

问题：并行写同一个仓库会冲突

Agent A 在改 app.py，Agent B 也在改 app.py。谁的修改会被覆盖？

核心思路：Git Worktree

Git worktree 让你从同一个仓库创建多个"工作树"——每个都有自己的目录和分支，但共享 git 历史。

  .worktrees/
  ├── feature-login/    ← Agent A 的工作树 (分支: wt/feature-login)
  │   └── app.py        (Agent A 的版本)
  ├── fix-bug-123/      ← Agent B 的工作树 (分支: wt/fix-bug-123)
  │   └── app.py        (Agent B 的版本)
  └── main/             ← 主仓库 (你们共享的 git 历史)

代码实现

def create_worktree(name, task_id=""):
    # 1. 验证名称（只允许字母数字和 ._-）
    validate_worktree_name(name)

    # 2. 创建 worktree + 新分支
    path = WORKTREE_DIR / name
    ok, result = run_git(["worktree", "add", str(path), "-b", f"wt/{name}", "HEAD"])

    # 3. 绑定到任务
    if task_id:
        bind_task_to_worktree(task_id, name)

    log_event("create", name, task_id)
    return ok, result

安全清理

删除 worktree 前检查是否有未提交的更改：

def remove_worktree(name, force=False):
    path = WORKTREE_DIR / name
    if not force:
        # 检查是否有未提交的更改
        ok, output = run_git(["-C", str(path), "status", "--porcelain"])
        if output.strip():
            return False, "Has uncommitted changes. Use force=True to override."

    # 安全删除
    run_git(["worktree", "remove", str(path)])
    return True, "Removed"

前端类比

Worktree 就像 Docker 容器——每个任务有自己的隔离文件系统，绑定到 CI/CD job。安全检查就像 docker rm 拒绝删除运行中的容器。

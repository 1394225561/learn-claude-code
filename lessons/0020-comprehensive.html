核心循环从未改变

回看第 1 课的循环，对比第 20 课的循环——核心逻辑完全一样：

# s01 的循环
while True:
    response = call_llm(messages)
    if not tool_use: return
    execute_tools()

# s20 的循环 —— 只是在外围加了层
while True:
    prepare_context(messages)          # + 压缩
    prompt = assemble_system_prompt()  # + 动态提示词
    tools = assemble_tool_pool()       # + MCP 工具
    response = call_llm(messages, tools, recovery_state)  # + 重试
    if not tool_use:
        trigger_hooks("Stop")          # + Stop hook
        return
    for block in tool_uses:
        trigger_hooks("PreToolUse")    # + 权限检查
        if background: ...             # + 后台执行
        execute_tool()
        trigger_hooks("PostToolUse")   # + 日志
    collect_background_results()       # + 收集后台结果
    consume_cron_queue()               # + 消费定时任务

循环是骨架，其他都是肌肉和皮肤。骨架不变，肌肉可以随意增减。

设计原则总结

  1. 模型决策，Harness 执行：代码不做判断，只执行模型要求的
  2. 循环不变性：所有机制都叠加在循环外围，循环本身不改
  3. 开闭原则：通过调度表和 hook 系统，新增能力不需要修改已有代码
  4. 上下文隔离：子 Agent 有独立的消息列表，避免污染
  5. 渐进式复杂度：从 30 行开始，按需叠加
  6. 文件即数据库：所有持久化都用扁平文件（JSON/JSONL），无数据库

第 6 课: Subagent — 子 Agent

当任务太复杂时，上下文会爆炸。这一课让 Agent 能派出"分身"去独立处理子任务，只把结论带回来。

问题：上下文不够用了

假设 Agent 要"分析这个项目的所有 Python 文件并生成文档"。如果把每个文件的内容都读进来，上下文很快就满了。

更糟的是，中间过程（读了哪些文件、哪些分析失败了）对最终结果没用，却占着宝贵的上下文空间。

核心思路：上下文隔离

创建一个"子 Agent"，给它一个全新的消息列表（不共享父级的对话历史），让它独立完成任务，只返回最终结论。

  父 Agent                    子 Agent
  ┌─────────────┐            ┌─────────────┐
  │ messages[50] │  ──任务──> │ messages[1] │  ← 全新上下文
  │ (很拥挤)     │            │ (只有任务)   │
  └─────────────┘            └──────┬──────┘
                                    │ 执行 30 轮
                                    │ 独立调用工具
                                    ▼
  ┌─────────────┐            ┌─────────────┐
  │ 收到结论     │  <──结论── │ 丢弃历史     │
  │ messages[51] │            └─────────────┘
  └─────────────┘

代码实现

def spawn_subagent(description: str) -> str:
    # 1. 全新上下文，只有任务描述
    messages = [{"role": "user", "content": description}]

    # 2. 独立循环，最多 30 轮
    for _ in range(30):
        response = client.messages.create(
            model=MODEL, system=SYSTEM,
            messages=messages,
            tools=SUB_TOOLS,  # 注意：没有 "task" 工具！
            max_tokens=8000,
        )
        messages.append({"role": "assistant", "content": response.content})

        if response.stop_reason != "tool_use":
            break

        # 执行工具（和父 Agent 一样的逻辑）
        results = []
        for block in response.content:
            if block.type == "tool_use":
                output = TOOL_HANDLERS[block.name](**block.input)
                results.append({"type": "tool_result",
                                "tool_use_id": block.id, "content": output})
        messages.append({"role": "user", "content": results})

    # 3. 只返回最终结论，中间历史全部丢弃
    return extract_text(messages[-1]["content"])

防止无限递归

子 Agent 的工具列表 SUB_TOOLS 里不包含 "task" 工具。这意味着子 Agent 不能再派子 Agent，避免了无限递归。

# 父 Agent 的工具：包含 task
TOOLS = [bash, read_file, write_file, ... , task]

# 子 Agent 的工具：没有 task
SUB_TOOLS = [bash, read_file, write_file, ...]  # 没有 task！
为什么文件系统副作用会保留？子 Agent 创建的文件是真的——因为 bash 和 write_file 执行的是真实命令。被丢弃的只是对话历史，不是文件操作。

前端类比

子 Agent 就像 Web Worker：

Web WorkerSubagent
独立线程独立消息列表
不共享主线程状态不共享父级对话历史
通过 postMessage 返回结果只返回最终文本结论
Worker 不能再嵌套 Worker子 Agent 不能再派子 Agent

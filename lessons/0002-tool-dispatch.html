第 2 课: Tool Dispatch — 工具调度

上一课只有一个 bash 工具。这一课我们给 Agent 5 个真正的工具，并用一个调度表让扩展工具变得零成本。

问题：只有 bash 太原始了

用 bash 读文件要 cat，写文件要 echo ... >，编辑文件要用 sed。又丑又容易出错。

能不能给模型更精确的工具？比如 read_file、write_file、edit_file？可以。但如果每加一个工具就改循环代码，那就太蠢了。

核心思路：调度表

把"工具名 → 执行函数"的映射抽成一个字典（类似 JS 的对象），循环代码永远不变：

# 工具调度表 — 类似前端的路由表
TOOL_HANDLERS = {
    "bash":       run_bash,
    "read_file":  run_read,
    "write_file": run_write,
    "edit_file":  run_edit,
    "glob":       run_glob,
}

# 循环中只需要一行
output = TOOL_HANDLERS[block.name](**block.input)
前端类比：这就像 React 的 <Icon name="..." /> 组件——渲染管线不变，你只需要在注册表里加一行。

工具定义：告诉模型有什么

除了执行函数，还需要用 JSON Schema 告诉模型每个工具的用途和参数：

TOOLS = [
    {
        "name": "bash",
        "description": "Run a shell command.",
        "input_schema": {
            "type": "object",
            "properties": {
                "command": {"type": "string"}
            },
            "required": ["command"],
        },
    },
    {
        "name": "read_file",
        "description": "Read a file's content.",
        "input_schema": {
            "type": "object",
            "properties": {
                "path": {"type": "string"}
            },
            "required": ["path"],
        },
    },
    # ... 更多工具
]

模型看到这些定义后，就知道什么时候该调哪个工具。

循环的变化

对比上一课，循环的唯一变化是把 run_bash(block.input["command"]) 换成了：

for block in response.content:
    if block.type == "tool_use":
        handler = TOOL_HANDLERS.get(block.name)  # 从调度表查找
        if handler:
            output = handler(**block.input)        # ** 展开参数
        else:
            output = f"Unknown tool: {block.name}"

**block.input 是 Python 的字典展开语法，等价于 JS 的 ...block.input，但它是按参数名传入函数的。

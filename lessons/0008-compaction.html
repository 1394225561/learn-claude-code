第 8 课: Context Compact — 上下文压缩

对话越来越长，上下文窗口会满。这一课用四层压缩策略保持上下文精简。

四层压缩管线

从便宜到昂贵，逐层应用：

层策略成本做法
L3tool_result_budget最低大结果存磁盘，只留预览
L1snip_compact低消息超 50 条时裁剪中间，保留头尾
L2micro_compact低旧工具结果替换为一行摘要
L4compact_history最高用 LLM 生成完整对话摘要

核心代码

def prepare_context(messages):
    """每轮调用 LLM 前执行"""
    messages[:] = tool_result_budget(messages)  # L3: 大结果存盘
    messages[:] = snip_compact(messages)        # L1: 裁剪中间
    messages[:] = micro_compact(messages)       # L2: 旧结果摘要
    messages[:] = compact_history(messages)     # L4: LLM 摘要
messages[:] = ... 是 Python 的切片赋值——原地修改列表内容，而不是创建新列表。JS 里你会写 messages.splice(0, messages.length, ...newItems)。

每层详解

L3: tool_result_budget — 大结果存磁盘

def tool_result_budget(messages, max_chars=5000):
    for msg in messages:
        if isinstance(msg.get("content"), list):
            for block in msg["content"]:
                if block.get("type") == "tool_result":
                    content = block.get("content", "")
                    if len(str(content)) > max_chars:
                        # 存磁盘，只留预览
                        path = save_to_disk(content)
                        block["content"] = f"[Saved to {path}]\n{str(content)[:500]}"
    return messages

L1: snip_compact — 裁剪中间消息

def snip_compact(messages, max_messages=50):
    if len(messages) <= max_messages:
        return messages
    # 保留前 10 条 + 后 20 条，中间用摘要替代
    head = messages[:10]
    tail = messages[-20:]
    return head + [{"role": "user", "content": "[Earlier messages compacted]"}] + tail

这就是 react-window 虚拟列表 + Service Worker 缓存淘汰策略。只渲染可见行，中间空白；缓存满了先淘汰最老的。

第 10 课: System Prompt — 动态提示词组装

之前系统提示词是硬编码的字符串。这一课把它变成按运行时状态动态组装的模块化系统。

问题：硬编码的提示词不灵活

随着 Agent 越来越复杂（有工具、有记忆、有技能、有 MCP），系统提示词需要包含越来越多信息。但不是每次都需要所有信息——没有记忆时不需要注入记忆索引，没连 MCP 时不需要 MCP 描述。

核心思路：分段注册，按需组装

# 每个段落注册到字典
PROMPT_SECTIONS = {
    "identity":  lambda ctx: "You are a coding agent...",
    "tools":     lambda ctx: f"Available tools: {ctx['tool_names']}",
    "workspace": lambda ctx: f"Working directory: {ctx['cwd']}",
    "memory":    lambda ctx: ctx.get("memory_index", ""),
}

def assemble_system_prompt(context):
    sections = []
    for name, builder in PROMPT_SECTIONS.items():
        content = builder(context)
        if content:  # 空内容不注入
            sections.append(content)
    return "\n\n".join(sections)

缓存：避免重复组装

如果上下文没变，提示词也不需要重新组装。用一个缓存键来判断：

_last_context_key = None
_last_prompt = None

def get_system_prompt(context):
    global _last_context_key, _last_prompt
    # 用 JSON 作为确定性缓存键（不能用 hash，因为 Python hash 会随机化）
    key = json.dumps(context, sort_keys=True)
    if key == _last_context_key:
        return _last_prompt  # 缓存命中
    _last_prompt = assemble_system_prompt(context)
    _last_context_key = key
    return _last_prompt
为什么不用 Python 的 hash()？Python 的 hash() 在每次运行时会随机化（安全特性），所以同样的输入会产生不同的哈希值。json.dumps(sort_keys=True) 是确定性的。

前端类比

PythonJavaScript说明
lambda ctx: expr(ctx) => exprPython lambda 只能单表达式，JS 箭头函数可多行
json.dumps(ctx, sort_keys=True)无直接等价确定性序列化（JS 的 JSON.stringify 不排序键）
global _last_prompt无直接等价函数内修改模块级变量需显式声明

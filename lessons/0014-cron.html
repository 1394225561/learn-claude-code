第 14 课: Cron — 定时任务

让 Agent 能够定时执行任务——每天早上跑一次测试、每小时检查一次构建状态。

核心思路

四层架构：

  1. 调度器（daemon 线程）：每秒轮询一次，检查 cron 表达式是否匹配
  2. 队列：匹配的任务放入线程安全队列
  3. 队列处理器：Agent 空闲时，把队列中的任务注入为消息
  4. Agent Loop：消费消息，正常执行
  ┌──────────────┐     ┌────────┐     ┌──────────────┐     ┌───────────┐
  │ Cron 调度器   │ ──> │  队列   │ ──> │ 队列处理器    │ ──> │ Agent Loop│
  │ (每秒轮询)    │     │        │     │ (空闲时注入)  │     │ (执行)    │
  └──────────────┘     └────────┘     └──────────────┘     └───────────┘

Cron 表达式

@dataclass
class CronJob:
    id: str
    cron: str        # "0 9 * * *" = 每天早上 9 点
    prompt: str       # 要执行的任务描述
    recurring: bool   # 是否重复
    durable: bool     # 是否持久化到磁盘

5 字段 cron 格式：分 时 日 月 周

表达式含义
0 9 * * *每天 09:00
*/5 * * * *每 5 分钟
0 0 * * 1每周一 00:00

线程协作

调度器和 Agent Loop 运行在不同线程，通过 agent_lock 协调：

# 调度器：只有 Agent 空闲时才注入任务
if agent_lock.acquire(blocking=False):  # 非阻塞获取锁
    cron_queue.append(job)
    agent_lock.release()

# Agent Loop：每轮开始前消费队列
def consume_cron_queue():
    while cron_queue:
        job = cron_queue.pop(0)
        messages.append({"role": "user", "content": f"[Scheduled] {job.prompt}"})

前端类比

这就是 setInterval + 消息队列。调度器像 Service Worker 的 periodicSync，队列处理器像 Redux middleware。

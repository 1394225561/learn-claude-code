第 1 课: Agent Loop — 一个循环就够了

这是你的第一个 Agent。它只有 一个循环 和 一个工具，但这已经是一个真正的 Agent 了。

问题：为什么需要一个循环？

假设你问 Claude："帮我看看当前目录有哪些 Python 文件"

模型可以输出一条 bash 命令：ls *.py。但输出之后它就停了——它不会自己执行，也不会看到结果后继续推理。

你可以手动执行命令，把输出粘贴回去，让模型继续。但每一步你都在做"中间人"。

Agent Loop 就是把这个"中间人"自动化。

核心思路

  +----------+      +-------+      +---------+
  |   用户   | ---> |  LLM  | ---> |  工具   |
  |  输入    |      |       |      |  执行   |
  +----------+      +---+---+      +----+----+
                        ^               |
                        |   tool_result |
                        +---------------+
                        (循环继续)

逻辑极其简单：

信号含义循环动作
stop_reason == "tool_use" 模型说："我要用工具" 执行工具 → 结果喂回去 → 继续循环
stop_reason != "tool_use" 模型说："我做完了" 退出循环

代码解析

让我们一步步看这个循环是怎么工作的。首先，用户输入一条消息：

messages = [{"role": "user", "content": "帮我看看当前目录有哪些文件"}]

然后进入循环，把消息和工具定义一起发给 LLM：

response = client.messages.create(
    model=MODEL,
    system=SYSTEM,       # 系统提示词，告诉模型它的角色
    messages=messages,    # 对话历史
    tools=TOOLS,          # 可用工具列表
    max_tokens=8000,
)

把模型的回答追加到对话历史中：

messages.append({"role": "assistant", "content": response.content})

检查模型是否要调用工具。如果不调用，循环结束：

if response.stop_reason != "tool_use":
    return  # 模型说完了，退出

如果模型要调用工具，执行它并收集结果：

results = []
for block in response.content:
    if block.type == "tool_use":
        output = run_bash(block.input["command"])  # 执行 bash 命令
        results.append({
            "type": "tool_result",
            "tool_use_id": block.id,
            "content": output,
        })

把工具结果作为新消息，回到循环顶部：

messages.append({"role": "user", "content": results})
# 回到 while True，继续下一轮

完整代码

把上面的步骤组装起来，不到 30 行：

def agent_loop(messages):
    while True:
        # 1. 调用 LLM
        response = client.messages.create(
            model=MODEL, system=SYSTEM, messages=messages,
            tools=TOOLS, max_tokens=8000,
        )
        # 2. 追加助手回复
        messages.append({"role": "assistant", "content": response.content})

        # 3. 模型不调工具 → 结束
        if response.stop_reason != "tool_use":
            return

        # 4. 执行工具，收集结果
        results = []
        for block in response.content:
            if block.type == "tool_use":
                output = run_bash(block.input["command"])
                results.append({
                    "type": "tool_result",
                    "tool_use_id": block.id,
                    "content": output,
                })
        # 5. 工具结果喂回去，继续循环
        messages.append({"role": "user", "content": results})
关键洞察：这个循环就是 Agent 的"内核"。后面所有课程（工具系统、权限、记忆、多 Agent）都是在这个循环上叠加机制，循环本身永远不变。

前端类比

如果你有前端经验，可以这样理解 Agent Loop：

// 前端类比：事件循环
while (true) {
  const event = await getNextEvent();   // 等待用户输入或 API 响应
  if (event.type === 'done') break;     // 退出条件

  const result = await executeHandler(event);  // 执行处理函数
  emit('result', result);               // 把结果发回去
}

Agent Loop 本质上就是一个事件循环：模型产生"事件"（工具调用），harness 处理事件并返回结果，循环继续。

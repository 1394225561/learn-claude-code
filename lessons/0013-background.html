第 13 课: Background Task — 后台任务

npm install 要跑 30 秒，Agent 干等着？这一课让慢任务在后台运行，Agent 继续干别的。

问题：慢操作阻塞循环

pip install、npm install、docker build 这些操作可能要几十秒。如果 Agent Loop 等着它完成，整个对话就卡住了。

核心思路：Daemon 线程

import threading

background_tasks = {}
background_results = {}
background_lock = threading.Lock()
_bg_counter = 0

def start_background_task(block) -> str:
    global _bg_counter
    _bg_counter += 1
    bg_id = f"bg_{_bg_counter:04d}"

    background_tasks[bg_id] = {"status": "running", "command": block.input}

    def worker():
        result = execute_tool(block)  # 在新线程中执行
        with background_lock:
            background_tasks[bg_id]["status"] = "completed"
            background_results[bg_id] = result

    threading.Thread(target=worker, daemon=True).start()
    return bg_id  # 立即返回 ID，不等结果

收集结果

def collect_background_results():
    """每轮循环开始时，检查有没有完成的后台任务"""
    results = []
    with background_lock:
        for bg_id, result in list(background_results.items()):
            results.append(f"[{bg_id} completed]\n{result}")
            del background_results[bg_id]
    return results

Agent 每轮循环开始时检查一次，把完成的结果注入消息列表。

前端类比

这就是 Web Worker + 通知队列。Python 的 threading.Thread 是真正的 OS 线程（不是 JS 的事件循环），类似 Web Worker 在独立线程中执行。完成后通过通知注入结果，像 toast 一样："后台任务完成了！"

Python 语法速查
